# 05 · 功能、安全与边界审阅清单（供项目负责人拍板）

在你正式批准启动 Phase 1 编码之前，请重点核对以下 **6 个核心设计点** 是否完全符合你的预期、是否存在安全或边界遗漏：

---

## 1. 功能设定是否满足需求？
- [ ] **只存纯文本 + 本地指针（Phase 1–2）**：代码、大型 `.db`/`.nc`、结果图留在本地磁盘与 Git，阿里云 Hub 只存文本对话、决策、任务状态与路径指针，暂不接 OSS。
- [ ] **三层上下文读取配比**：
  - 新任务首次启动（支持直接按 Chat 名称开工）：当前有效 `APPROVED` 决策 + 阶段摘要（如有）+ 来源窗口最近 **15–20 轮**原文。
  - 模型间交接：当前有效 `APPROVED` 决策 + 来源窗口最新 **5 轮**原文 + 上一模型的**交接摘要 + 执行现场最新 ~10 轮原文 + `git diff` 补丁**。
- [ ] **正式决策支持更新换代**：`APPROVED` 决策可通过版本替代更新（新决策生效为 `APPROVED`，旧决策自动变为 `SUPERSEDED` 永久留档），执行 AI 默认只遵守最新有效版本。
- [ ] **Chrome 扩展无需应用商店上架**：采用 Manifest V3 开发者模式本地加载 `extension/` 目录即可永久自用与即时更新。
- [ ] **DeepSeek 1M 滚动压缩规则**：保留最新 20 轮原文不压缩；更早的未压缩旧对话累计达 **150K–250K 字符**时触发 DeepSeek 压成 **4K–6K 字**阶段纪要，原文永不删除且可全文搜索。
- [ ] **三端本地日志提取**：通过本机轻量脚本直接解析 Claude Code / Codex / Antigravity 的 `.jsonl` 日志生成高保真交接包，**不额外浪费模型额度总结，即使突发额度耗尽也能接手**。

## 2. Chat Bridge 习惯是否顺手？
- [ ] **白名单制**：只有明确绑定的工作窗口才同步，日常闲聊窗口完全忽略。
- [ ] **抓包时机**：以“你发下一轮时读取上一轮”为主 + “生成结束 3 秒静默兜底”为辅，配合 `message_hash` 去重。
- [ ] **历史补齐**：去掉繁琐的官方 ZIP 导入，改用“点击按钮时在当前已登录页面同源拉取该会话历史”（Cookie 绝不出本机浏览器）。
- [ ] **可选自动发送**：默认只填入不发送；仅在明确勾选 `auto_send_enabled` 的白名单窗口开启自动发送，并带冷却间隔、5 次自动熔断与顶部急停开关。

## 3. 安全与边界隐患自检
- [ ] **开源不泄密**：后续开源到 GitHub 时，仓库中已配置 `.gitignore` 屏蔽 `.env`、密钥、数据库、`.jsonl` 与证书；**严禁将任何 API Key / Token 写入代码或文档**。（注意：任何曾在聊天或测试中出现过的密钥，生产上线前建议轮换一次或仅在本地 `.env` 注入。）
- [ ] **防越权批准决策**：三个执行 AI 的 `Agent Token` 物理无权批准决策（只能提议 `PROPOSED`），也无权删除永久档案。
- [ ] **防网页对话 Prompt 注入**：历史对话严格包裹为只读参考数据，不视作系统命令。
- [ ] **防双模型同时改同一代码文件**：`claim_task` 使用数据库行锁防并发领取；并行任务要求开独立 Git 分支或 Worktree。
- [ ] **防现有波导业务受影响**：Hub 独占子域名 `hub.atmosphericduct.xyz` + `127.0.0.1:8100` + 独立 Python 3.11 环境，不碰现有 `127.0.0.1:5000` 和波导数据库。

## 审阅通过后的下一步（Phase 1 启动标准）
当你确认上述清单无误后，我们将按以下顺序推进 Phase 1：
1. 在阿里云安装 Python 3.11 独立环境与 PostgreSQL（低内存调优 + 每日 `pg_dump` 备份）；
2. 在 `server/` 实现核心数据库迁移（Alembic）、鉴权、三类档案 API 与单元测试；
3. 将 `hub.atmosphericduct.xyz` 的 Nginx 占位切换为真实反代，并校验健康检查与权限拦截测试全部通过。
