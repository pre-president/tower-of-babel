# 04 · Chrome Extension（Chat Bridge）交互与边界设计

本文件描述网页端 `chatgpt.com` 与阿里云中枢之间的桥接逻辑，供你审阅“日常用起来顺不顺手、会不会乱同步、自动发送安不安全”。

---

## 1. 核心原则：白名单驱动，不干扰日常闲聊

- **未绑定窗口**：你平时新开的查资料、写邮件、日常闲聊窗口，**默认完全不抓取、不上传、不弹窗打扰**。
- **已绑定窗口**：只有当你在浏览器右侧边栏（Side Panel）点击 **“绑定到工作区（选择或新建 `planner_thread_id`）”** 后，该会话 UUID 才进入本地白名单并激活同步与问题队列。

---

## 2. 增量抓取与防半成品机制

针对 `chatgpt.com` 页面特性，采用 **“主时机 + 兜底时机 + Hash 去重”**：

1. **主时机（你发出下一轮消息时）**：
   - 当你在绑定窗口按下发送（Enter 或点击发送按钮）发起新一轮提问时，扩展立即扫描上一轮用户提问与 ChatGPT 的最终回答。
   - **优势**：此时上一轮输出 100% 已完全结束并稳定渲染在页面上，彻底避开打字机流式跳动导致的残缺数据。
2. **静默兜底时机（聊完最后一轮不再发下一句时）**：
   - 通过 `MutationObserver` 监听“停止生成”按钮消失且输出区域连续 **3 秒**无文本变化后，自动触发一次抓取；如果刚才已同步过，服务端的 `message_hash` 自动去重，零重复记录。
3. **Markdown 与公式保留**：
   - 提取时针对代码块（`<pre><code>`）与公式节点（KaTeX `annotation` / TeX 源码）做保真还原，尽量保留原始 Markdown 与公式格式。
4. **断网/服务器重启本地重试队列**：
   - 若某次上传因网络波动失败，暂存进浏览器 `chrome.storage.local` 的待重试队列，网络恢复后按序补传。

---

## 3. 历史旧对话全量读取（非常驻，按需触发）

根据你的需求，**v1 版不做官方 ZIP 导入器**；当你偶尔需要把一个已经聊了上百轮的旧窗口纳入 Hub 时：
- 在侧边栏点击 **“全量同步本窗口历史”**；
- 扩展在**你当前已登录的 `chatgpt.com` 页面同源环境**中，利用浏览器自身有效会话拉取一次该 `conversation_id` 的完整对话树 JSON（Cookie 永远保留在你自己浏览器里，**绝不上传至阿里云服务器**）；
- 扩展在浏览器本地将树状结构展平为按时间顺序的可见文本轮次，分批（如每 50 条一批）推送到 Hub 并由 `message_hash` 去重。
- **防风控约束**：仅在用户手动点击时执行单次请求，**绝不在后台定时轮询或批量扫全账号所有历史对话**。

---

## 4. 上下文注入与问题队列（含“白名单可选自动发送”）

### 4.1 上下文读取注入
在侧边栏提供一键操作按钮（结果先在侧边栏预览可剪裁，点击“填入输入框”后由你确认发送）：
- **Load Project Context**：拉取项目最新 `APPROVED` 决策与当前任务进展。
- **Search Dialogue**：输入关键词检索全部相关工作窗口的历史片段并引用到当前对话。
- **Review Proposed Decisions**：查看执行 AI 提交的待审批决策建议，点击“批准”正式写入 `Decision Archive`。

### 4.2 问题队列 & 白名单可选自动发送
当 DeepSeek / Gemini / Codex 调用 `submit_question` 向某个 `planner_thread_id` 提问后：
1. 侧边栏对应窗口的“待回答队列”计数 `+1`，显示提问来源（哪个模型、哪个任务、卡点证据与影响）。
2. **两种模式（按每个绑定窗口独立配置）**：
   - **默认模式（`auto_send_enabled = false`，安全人工确认）**：你点击问题卡片上的“填入提问”，扩展跳转到对应 ChatGPT 标签页并填入输入框，由你审阅后手动按发送。
   - **白名单自动模式（`auto_send_enabled = true`，仅你主动勾选的窗口生效）**：
     - 扩展收到待回答问题时，检查目标窗口标签页是否打开且处于**空闲状态**（未在生成中、输入框为空）；
     - 自动将问题上下文填入输入框并模拟触发发送按钮；
     - 等待 ChatGPT 生成完毕、自动同步回答后，调 `resolve_question` 把答案回传 Hub，解除对应任务的 `WAITING_FOR_DECISION` 阻塞。
3. **可选自动发送的四重安全护栏（防失控、防循环刷屏）**：
   - **白名单隔离**：仅对明确勾选了该选项的 `planner_thread_id` 生效，新绑定窗口默认关闭；
   - **冷却节流**：同一窗口两次自动发送之间至少间隔 **15 秒**，且连续自动发送超过 **5 次**未经过人工交互时自动暂停并提醒；
   - **防回环保护**：自动发出的问题带标记，禁止执行 AI 把 ChatGPT 的回答不经任务推进又立刻无限递归自动提问；
   - **总急停开关**：侧边栏顶部置顶一个全局 **“暂停全部自动发送”** 开关，随时一键熔断。

## 5. DOM 改版防脆弱设计
OpenAI 不定期微调前端样式类名，因此扩展代码采用**适配器隔离设计**：
- 所有页面选择器（输入框、发送按钮、停止按钮、消息角色属性 `data-message-author-role`）集中收敛在单一 `dom-adapter.js` 文件中，不依赖随机哈希类名；
- 一旦发现页面结构更新导致无法定位输入框，立即降级为“侧边栏复制到剪贴板并提示”，**绝不静默丢消息或胡乱点击页面其他按钮**。
